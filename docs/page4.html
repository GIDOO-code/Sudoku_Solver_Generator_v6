Sudoku Standardization

Sudoku puzzles Conversion and standardization

Sudoku puzzles can change their appearance while remaining valid under certain conditions.
Swapping digits or transforming the sequence of digits into a different order—such as changing (634581279) to (123456789)— results in a puzzle that remains valid.

>

Furthermore, the puzzle remains valid even if swap columns 1 and 2, cyclically shift columns (1→2→3→1), swap column groups (columns 1–3 with columns 4–6), perform similar operations on rows, swap rows and columns (transposition), or apply combinations of these operations.
However, transformations that violate Sudoku constraints—such as swapping column 1 with column 4—are not permitted.
Since rotations can be expressed as combinations of row-column swaps and vertical or horizontal flips, they are not considered here.




Furthermore, even when such transformations are applied, the method for solving the Sudoku puzzle remains the same. The difficulty level and the analysis algorithms applicable at each stage are also identical.
In solving Sudoku, there are instances where multiple algorithms can be applied to a single board state. The choice of algorithm depends on the solver's preference or the program's implementation, leading to some—or even significant—differences in the solving process. i will simply disregard such differences.

A Sudoku puzzle is a combination of a pattern of given-digit positions and a Latin square that satisfies the block constraints of the solution.
The "canonical form" of a Sudoku puzzle can be defined by combining the canonical forms of the pattern and the Latin square. Of course, simply combining a pattern and a Latin square does not necessarily result in a valid Sudoku puzzle; it might be unsolvable or have multiple solutions. The puzzle generation function in GNPX creates a puzzle by combining a Latin square with a given-digit position pattern, and then tests whether it can be solved using analysis algorithms.
(Starting with GNPX Ver.7, a generation method using DLX has been added.)

Below, formally define the transformation of Sudoku puzzles and establish a method for their standardization.

Sudoku Puzzle Transformation (Asymmetric Transformation)

A Sudoku puzzle remains valid even after operations such as swapping rows or columns, transposing the grid, or combining these transformations. However, transformations that violate Sudoku rules (such as block constraints)—for instance, swapping column 1 with column 4—are not permitted. Transformations that adhere to these constraints can be classified and organized as follows:

  1. Row band permutation
    Group rows 1,2,and 3 together as row band-. Similarly, group rows 4,5,and 6 as row band-2, and rows 7,8,and 9 as row band-3. The row bands can be permuted arbitrarily. There are 3!=6 possible permutations.

  2. Permutation within row band n(n=1,2,3)
    The rows a,b,and c within row band-n can be permuted arbitrarily. There are 3!=6 possible permutations.

  3. Column band permutation
    Group columns 1,2,and 3 together as column band-1. Similarly, group columns 4,5,and 6 as column band-2, and columns 7,8,and 9 as column band-3. The column bands can be permuted arbitrarily. There are 3!=6 possible permutations.

  4. Permutation within column band n(n=1,2,3)
    The columns a,b,and c within column band-n can be permuted arbitrarily. There are 3!=6 possible permutations.

  5. Transposition of rows and columns
There are a total of (3!)8×2 = 3,359,232 such transformations.

Transformation of Sudoku Puzzles (Symmetric Transformation)

When a constraint of point symmetry about a certain center is imposed on the pattern in question, the transformation takes the following form.

  1. Mirror-image swap of row band-1 and -3
    Swap rows 1,2,and 3 with rows 9,8,and 7, respectively.

  2. Mirror-image transformation of row band 3 linked to the transformation of row band 1
    Perform a mirror-image transformation on rows 7,8,and 9 linked to any transformation of rows 1,2,and 3. For example, swap rows 7 and 9 in conjunction with swapping rows 1 and 3. There are 3!(=6) possible variations of this transformation.

  3. Swap of rows 4 and 6

  4. Mirror-image swap of column bands 1 and 3
    Swap columns 1,2,and 3 with columns 9,8,and 7, respectively.

  5. Mirror-image transformation of column band 3 linked to the transformation of column band 1
    Perform a mirror-image transformation on columns 7,8,and 9 linked to any transformation of columns 1,2,and 3. For example, swap columns 7 and 9 in conjunction with swapping columns 1 and 3. There are 3!(=6) possible variations of this transformation.

  6. Swap of columns 4 and 6

  7. Transposition of rows and columns
There are(2x3!x2)2x2=1,152 possible simple point-symmetry transformations. These transformations preserve symmetry when the original problem involves a point-symmetric pattern, and preserve asymmetry when the pattern is asymmetric.



Sudoku Standardization

0. Define the Sudoku Standard Code.

Define a "Standard code" that uniquely represents isomorphic Sudoku grids (isomorphic variants generated by digit permutation, transposition, swapping of row or column bands, and swapping of rows or columns within a band). Note that puzzles with multiple solutions are excluded from this scope.


1.Procedure for Setting Standard Codes (Overview)

The “standard code” is defined through a two-stage normalization process. First, an overview (the underlying concept) of the standard code configuration is presented.

(1) Normalization of hint positions
First, focus on the positions of the hints in the puzzle (the specific hint digits do not matter).
Consider applying operations such as transposition, swapping row bands, swapping rows within a row band, swapping column bands, and swapping columns within a column band to the puzzle.
Applying such swapping operations does not alter the fundamental nature of the puzzle.
The "hint position index" can be defined arbitrarily, provided that the ordering of hint positions can be represented as a unique index.

Method 1：
Represent the presence or absence of clues in the puzzle's rows (r1, r2, r3, ...) as a binary sequence (1/0) and treat the configuration of all nine rows as a single numerical value.
This metric characterizes the pattern of clues within the row bands; intuitively, this is a natural approach.
However, this method also affects the column bands (c123, c456, c789) due to the constraints imposed by the blocks.
This propagation of constraints (interference) complicates the logic required to uniquely determine the ordering of the metrics.

Method 2：
The presence or absence of a hint for each block (b1=r123c123, b2, b3, ...) is represented as 1 or 0, and the block indicators are arranged in row-major order to form the board indicator.
Since this method proceeds by resolving each block individually, the logic for calculating the standard code is relatively simple.

Normalizing the hint positions in the standard code can be achieved using either Method 1 or Method 2 (I have actually tested both).
GNPX adopts Method 1 (row-based normalization), prioritizing human intuition.


(2)Normalization of hint digits
Arbitrarily swapping the digits in a Sudoku puzzle does not alter the fundamental nature of the problem.
Normalizing the puzzle's digits requires, as a first step, the complete numerical layout of the solved puzzle board.
An ordering based on the "hint digits" is then established using the numerical arrangement of the solved board.
While this ordering can be defined in various ways—such as by row or by block—we adopt "row-based number normalization, " consistent with the normalization of hint positions.



2. Method for setting standard codes (details)

2.1 Normalization of hint positions

Normalization of the hint position is performed according to the following procedure.

(1)R1C123
Focusing on 1x3 cells across the entire board, perform permutations along the columns to determine the minimum numerical representation for a 1x3 cell. Place the 1x3 cell with this minimum value at r1c123.
Since there are often multiple such 1x3 cells, all of them are considered candidates.

(2)r1c456789
Row-1 is determined based on the candidates from (1). Permutations are applied to the 1x3 cell groups r1c456 and r1c789 in row-1 to find the minimum numerical representation, which is then assigned to r1c456 and r1c789. This placement determines row 1 and columns c1–c9.
Since there are multiple possible arrangements for this configuration, all of them are treated as candidates.

(3)r2c1-9,r3c1-9
The values ​​for r1c1–9 are determined based on the candidates for r1. Additionally, the determination of the r1 candidates fixes the values ​​for the r2 and r3 rows within Band 1. The values ​​for r2c1–9 and r3c1–9 are placed by comparing the numerical representations of the 1x9 cell sequences for r2c1–9 and r3c1–9.

(4)Band2,3
Determine the minimum numerical representation for Band-2 and -3 by arranging the bands and permuting the rows within them, then place the values ​​for r4–9, c1–9.


Multiple exchange methods are possible for the "board index configuration pattern with the minimum value" obtained through these exchange operations.
To establish a standard code for the puzzle, an ordering based on the board's numerical values ​​is required as the next step.


2.2 Normalization using hint digits

Solve each puzzle converted in Step 2.1 to determine the final layout.
Next, transform the digits in Block 1 so that they correspond to the sequence "123456789"; this transformation does not alter the essential nature of the puzzle.
While listing every digit in the final layout could serve as an identifier for the puzzle, doing so is redundant.
Instead, by reverting the transformed final layout to the state corresponding to the original puzzle and using only the given hint digits, one obtains an identifier that characterizes the puzzle.
In the puzzle standardization process, the hint digits - arranged in row-column order - serve as a normalized indicator of the hint values.

The combination of these two characteristic values—"hint placement" and "hint digits"—defines the "standard code" for a Sudoku puzzle.

3.Standard code (example)

The standard code is a combination of the normalized indicator for the hint position and the normalized indicator for the hint digits.
The standard code is a character string.


Puzzle Standard Code : "6218146 2395576 297363589481 0o 000 111 226 000 143 424 454 611 650"

The standard code possesses the characteristics of visibility and reproducibility, as each digit of the octal value directly corresponds to the presence or absence of hints in each row (based on binary representation), allowing the original standard puzzle's cell layout to be reconstructed from the code alone.

4.Standardization Program

4.1 Standardization Program code
The standardization program code within GNPX is structured to be largely independent of the rest of the codebase.
This component can be extracted for learning and reuse purposes.

The standardization program code underwent the following verification tests:
・For a large number of puzzles, variants were generated by applying random swaps to each original puzzle; it was confirmed that these derived puzzles matched a single standard puzzle code.
・Verification was performed on a publicly available database of 17-clue puzzles (49,158 puzzles), confirming that every puzzle was unique.
  Additionally, a neighborhood search (-N/+N, where N=1,2) was conducted on the same database, confirming that no new puzzles were generated.
・The sample puzzles included with GNPX contain duplicates.
